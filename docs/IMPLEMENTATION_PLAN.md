# MEGAPOST 구현·검증 보고

## 완성된 플레이 경로

서울 서부의 신입 배송 운영 관리자가 D-204 냉장 배송, 기사 휴게와 픽업 마감, 단지 로봇 오배송을 처리한다. 마지막 보고 시간에는 현장 스캔으로 중복 배차를 조사할 수 있다. 재출근한 운영자는 전임자의 블랙박스를 찾아 강변으로 우회하거나 지난번 봉인 번호를 회수팀에 주고 오늘의 비행기록을 확보할 수 있다. 두 방법은 화물의 이동 경로와 마감 실적에 서로 다른 영향을 준다.

화면은 문제, 현재 목표, 선택별 행동과 비용을 함께 표시한다. 예비 무인차를 휴게 대체에 쓰면 오후 스캔에는 쓸 수 없으며 기사에게 확인하는 경로가 남는다. 입력 명령, 근무 재시작, 개인 로그와 저장 복원은 기존 순수 엔진의 계약을 활용한다. 사건표와 대표 경로에서 행동 단위로 확인할 수 있다. [사건과 선택](EVENT_SYSTEM.md) · [다섯 근무](PROGRESSION.md)

## 반복의 빈도와 발견성

시드 18400으로 매번 화면에 나타난 선택을 균등하게 고르는 독립 캠페인 10,000개를 각 6회 실행했다. 첫날 결과는 F1 자동 전환 17.76%, F2 마감 미달 30.46%, F3 중복 출고 30.87%, K1 근무 유지 20.91%였다. 1회부터 6회까지 새 기억을 하나 이상 얻은 캠페인 비율은 각각 100%, 47.20%, 26.28%, 15.81%, 10.99%, 9.38%였다.

6회 안에 단독 인계 K2를 한 번이라도 본 캠페인은 2,732개, 공동 신고 K3은 461개, 분리 실패 F4는 202개, 진엔딩 K4는 2개였다. 사고 기록을 따라간 고정 경로는 5회에 K4에 닿았다. 두 결과는 단서를 활용하는 전략과 맹목적인 반복 사이의 차이를 보여 준다. 초심자의 진엔딩 도달 시간과 실제 발견율은 사람 대상 플레이테스트에서 측정해야 한다.

## 후속 관찰

첫 선택 전 사용자가 어디에 무엇을 보내야 하는지 말할 수 있는지, 기사 휴게를 보장할 때 예비차의 오후 비용을 이해하는지, 중복 출고 뒤 다음 근무에 어떤 근거로 다르게 행동하는지 관찰한다. 후반에는 실물 배송을 끊지 않으려면 왜 사전 예약이 필요한지 이해하는지가 관건이다.

실기기 터치, Safari·Firefox, 모두의 AI의 임베드 저장·파일 권한은 미검증이다. 실제 이용자 메시지 서비스는 후속 범위다. 기존 판의 보존 위치와 이식 인수 절차는 [기술 구조](ARCHITECTURE.md)와 [이식 가이드](IMPORT_GUIDE.md)에 있다.
